截至2026年，**AI Agent（人工智能智能体）开发**已经成为大模型落地最核心、薪资最高的岗位之一。与传统的“大模型算法工程师”（侧重预训练和底层微调）不同，​**AI Agent 开发更偏向于“AI 应用架构与工程落地”**​，要求开发者既懂大模型的边界，又具备极强的软件工程能力。

以下是为您整理的 AI Agent 开发岗位的核心要求、技术框架及知识体系：

### 一、 需要哪些工作经验？

目前市场上纯粹的“应届生 Agent 开发”较少，该岗位通常要求候选人具备扎实的工程底座，多数由**高级后端工程师、搜索/推荐算法工程师、或早期的 NLP/对话系统工程师**转型而来。

1. ​**工作年限**​：通常要求 **3-5年以上** 软件开发或算法经验。
2. ​**核心项目经验**​：
   * ​**大模型应用落地经验**​：主导或核心参与过基于 LLM 的业务系统重构或新产品研发（如智能客服、自动化数据分析、代码助手、企业级知识库）。
   * ​**复杂工作流编排经验**​：有将非结构化任务拆解为多步骤、多工具调用的自动化工作流（Workflow）经验。
   * ​**高并发与系统架构经验**​：Agent 调用链路长、延迟高，需要丰富的异步编程、缓存设计、微服务架构经验来保障系统的稳定性和响应速度。
3. ​**加分经验**​：
   * 有开源 Agent 框架（如 LangChain, AutoGen, Dify 等）的贡献经验。
   * 有垂直领域（如金融、医疗、法律）的数据治理和知识图谱构建经验。

### 二、 需要掌握哪些技术框架？

Agent 开发的技术栈可以分为**模型交互层、编排与记忆层、数据与检索层、工程部署层**四大类：

#### 1. Agent 编排与多智能体框架 (核心)

* ​**LangGraph**​：目前最主流的基于图（Graph）的 Agent 状态机编排框架，适合构建复杂、多分支、需要人工介入（Human-in-the-loop）的 Agent。
* ​**AutoGen / CrewAI**​：主流的多智能体（Multi-Agent）协同框架，用于构建多个 Agent 角色分工、辩论、协作完成复杂任务。
* ​**Semantic Kernel (SK)**​：微软推出的企业级 AI 编排框架，对 C#/.NET 生态及企业级 API 集成非常友好。
* ​**Dify / Coze (扣子)**​：虽然是低代码/无代码平台，但高级开发岗需要深入理解其底层逻辑，甚至基于其开源版本进行二次开发和私有化部署。

#### 2. 工具调用与上下文协议 (2026年标配)

* ​**MCP (Model Context Protocol)**​：由 Anthropic 提出并成为行业标准的协议。​**必须掌握**​。它标准化了 Agent 与外部数据源、工具、IDE 之间的连接方式，是构建生态化 Agent 的基石。
* ​**Function Calling / Tool Use**​：熟练掌握各大模型（OpenAI, Claude, 智谱, 百川, 通义等）的函数调用机制及 JSON Schema 定义。

#### 3. RAG（检索增强生成）与向量数据库

* ​**LlamaIndex**​：处理复杂数据索引、多路召回、GraphRAG（基于知识图谱的 RAG）的首选框架。
* ​**向量数据库**​：Milvus, Qdrant, Weaviate, Chroma, PGVector。需要懂得如何根据业务场景选择，并进行索引优化（如 HNSW 调参）。
* ​**混合检索 (Hybrid Search)**​：BM25 + 向量检索 + 重排序（Rerank，如 BGE-Reranker）的融合策略。

#### 4. 后端工程与推理部署

* ​**后端语言**​：**Python** (FastAPI, Asyncio 异步编程是绝对主力)，部分高并发网关或业务层使用 ​**Go / Java / Rust**​。
* ​**推理部署**​：vLLM, SGLang, Ollama, Triton Inference Server。懂得如何私有化部署开源模型（如 Llama 3/4, Qwen 2.5/3 等）并优化吞吐量。

### 三、 需要掌握哪些核心知识？

#### 1. Agent 核心原理与架构

* ​**认知循环**​：深入理解 **ReAct** (Reasoning + Acting)、​**Plan-and-Solve**​、**Reflexion** (反思机制) 等 Agent 思考范式。
* ​**记忆系统 (Memory)**​：
  * ​**短期记忆**​：上下文窗口管理、对话历史压缩（Summarization）。
  * ​**长期记忆**​：基于向量库的语义记忆、基于知识图谱（GraphRAG）的结构化记忆、用户画像记忆。
* ​**规划与路由 (Planning & Routing)**​：如何将复杂任务拆解为子任务（DAG图），以及如何设计 Router Agent 将请求分发给最合适的子 Agent 或工具。

#### 2. Prompt Engineering (进阶)

* 不再是简单的“写提示词”，而是​**系统级 Prompt 架构设计**​。
* 掌握 CoT (思维链)、ToT (思维树)、Few-shot 动态注入、System Prompt 的模块化与版本控制。

#### 3. 大模型微调与对齐 (按需掌握)

* 虽然 Agent 开发不一定要从头预训练，但需要懂 **SFT (监督微调)** 和 ​**LoRA / QLoRA**​。
* ​**核心目的**​：当通用模型的 Function Calling 格式不稳定，或特定领域的“黑话/行话”理解不足时，能够通过微调让模型变成“专用 Agent 大脑”。

#### 4. Agent 评估与可观测性 (工程化痛点)

* ​**评估体系 (Evaluation)**​：如何评估 Agent 的任务完成率、工具调用准确率、幻觉率。掌握使用 LLM-as-a-Judge 或自动化测试集（如 AgentBench）进行评估。
* ​**可观测性 (Observability)**​：熟练使用 **LangSmith, LangFuse, Phoenix** 等工具，对 Agent 的每一步 Trace（思考、工具调用、耗时、Token消耗）进行追踪和 Debug。

#### 5. 安全与合规 (Guardrails)

* 提示词注入攻击（Prompt Injection）的防御。
* 工具调用的权限控制（沙箱机制、API 鉴权）。
* 输出内容的护栏（Guardrails）拦截机制。

### 四、 2026年行业最新趋势（面试加分项）

如果您正在准备面试或规划学习路线，请务必关注以下 2026 年的行业热点：

1. ​**从“单 Agent”到“多智能体社会 (Multi-Agent Society)”**​：企业级应用不再是单一 Agent 包打天下，而是由“规划者、执行者、审查者、代码沙箱”组成的 Agent 团队协同工作。
2. ​**端侧 Agent (On-Device Agent)**​：随着手机/PC 端侧大模型（如 7B-14B 量化模型）的成熟，如何在算力受限、隐私要求高的端侧设备上运行 Agent（结合 OS 级别的 API 调用）是巨大风口。
3. ​**GUI Agent / 计算机使用 (Computer Use)**​：Agent 不再仅仅调用 API，而是能够像人类一样“看”屏幕，通过模拟鼠标点击和键盘输入来操作传统的遗留软件系统（如 RPA 的 AI 升级版）。
4. ​**MCP 生态的深度应用**​：企业正在构建内部的 MCP Server 矩阵，将企业内部的 ERP、CRM、数据库全部封装为 MCP 标准接口供 Agent 调用。

### 五、 求职与准备建议

1. ​**准备一个“端到端”的硬核项目**​：不要只写一个“调用 API 查天气”的 Demo。建议做一个​**基于 LangGraph + MCP + RAG 的复杂业务 Agent**​（例如：能够自动读取 GitHub Issue，分析代码库，生成 PR 并自动运行测试的 DevOps Agent；或者能自动抓取财报、构建知识图谱并进行深度问答的金融分析 Agent）。
2. ​**强调“工程化”思维**​：在简历和面试中，多谈谈你如何解决 Agent 的​**延迟问题**​（如流式输出、并行工具调用）、​**成本控制**​（如小模型路由、缓存策略）、以及​**稳定性**​（如重试机制、降级策略、死循环检测）。
3. ​**关注开源社区**​：保持对 LangChain、LlamaIndex、Dify 等核心开源项目 Release Notes 的关注，了解社区正在解决什么痛点。

要成为一名优秀的 AI Agent 开发者，仅仅掌握写代码和调 API 是远远不够的。Agent 开发本质上是 ​**“用 AI 技术解决复杂业务问题”的系统工程**​。

以下为您将 Agent 开发所需的能力模型深度拆解为**技术内容（Hard Skills）** 和**非技术内容（Soft Skills & Cognitive Skills）** 两大维度，并详细标注了掌握程度（掌握/熟悉/了解）及其背后的业务逻辑。

### 一、 技术内容深度拆解 (Hard Skills)

技术能力是 Agent 开发的底座，建议按照以下六个层次进行构建：

#### 1. 大模型底层原理与交互 (Foundation)

* ​**掌握**​：
  * ​**Transformer 核心机制**​：不需要手撕代码，但必须深刻理解 Attention 机制、位置编码、**KV Cache** 原理。这决定了你如何优化上下文长度和推理成本。
  * ​**API 调用与 Token 经济学**​：精通各大主流模型（OpenAI, Claude, 国产头部模型）的 API 细节。能够精准计算 Token 消耗，进行成本估算与预算控制。
* ​**熟悉**​：
  * ​**微调技术 (PEFT)**​：掌握 LoRA、QLoRA 的原理与实操。知道在什么业务场景下，Prompt 已经失效，必须通过微调来注入领域知识或规范输出格式。
  * ​**对齐技术概念**​：理解 RLHF、DPO 的基本逻辑，能与算法团队顺畅沟通模型对齐的需求。
* ​**了解**​：预训练流程、分布式训练框架（DeepSpeed 等），以便评估算力需求。

#### 2. Agent 核心编排与架构 (Orchestration)

* ​**掌握**​：
  * ​**状态机与图编排**​：精通 **LangGraph** 或类似框架。能够设计包含条件分支、循环、人工介入（Human-in-the-loop）的复杂 Agent 工作流。
  * ​**思考范式 (Paradigms)**​：深入理解并能实现 ReAct（推理+行动）、Plan-and-Solve（规划+执行）、Reflexion（自我反思与纠错）等核心 Agent 认知循环。
  * ​**工具调用 (Tool Use)**​：精通 Function Calling 的 JSON Schema 设计。能够处理工具调用失败、参数缺失、死循环等异常情况。
* ​**熟悉**​：
  * ​**MCP (Model Context Protocol)**​：掌握 MCP Server/Client 的开发。能够将企业内部系统（ERP、CRM、数据库）标准化封装为 Agent 可调用的工具。
  * ​**多智能体协同 (Multi-Agent)**​：熟悉 AutoGen、CrewAI 等框架，理解 Agent 之间的通信机制、角色分配与冲突解决策略。
* ​**了解**​：主流开源框架的底层源码逻辑，具备二次开发和 Bug 排查能力。

#### 3. 数据工程与 RAG (Data & Retrieval)

* ​**掌握**​：
  * ​**文档解析与分块 (Chunking)**​：掌握按语义、按标题、递归等多种分块策略。知道如何处理 PDF、表格、代码等复杂格式。
  * ​**混合检索与重排序**​：精通“向量检索 (Dense) + 关键词检索 (Sparse/BM25)”的融合策略，并熟练使用 Rerank 模型（如 BGE-Reranker）进行二次排序，大幅提升召回准确率。
  * ​**向量数据库**​：精通 Milvus、Qdrant 或 PGVector 的索引构建（如 HNSW）、参数调优与性能监控。
* ​**熟悉**​：
  * ​**高级 RAG 策略**​：掌握 Query 改写（HyDE、Multi-query）、多路召回、GraphRAG（结合知识图谱的 RAG，解决全局理解问题）。
  * ​**多模态 RAG**​：能够处理图文、音视频等多模态数据的解析与检索。

#### 4. 软件工程与系统架构 (Engineering & Architecture)

* ​**掌握**​：
  * ​**异步与高并发编程**​：精通 Python 的 Asyncio、FastAPI。Agent 调用链路长、IO 密集，异步编程是保障系统吞吐量的核心。
  * ​**消息队列与解耦**​：熟练使用 Kafka、RabbitMQ 或 Celery。将长耗时的 Agent 任务异步化，避免阻塞主线程。
  * ​**缓存策略**​：精通 Redis 等缓存技术。对高频且确定的 Prompt 请求、中间状态进行缓存，大幅降低延迟和 Token 成本。
* ​**熟悉**​：
  * ​**微服务与容器化**​：熟悉 Docker、Kubernetes，能够编写高质量的 CI/CD 流水线。
  * ​**前端基础**​：熟悉 Streamlit、Gradio 或 React/Vue 基础，能快速搭建 Demo 或与前端团队高效协作。

#### 5. 推理部署与优化 (Inference & Optimization)

* ​**掌握**​：
  * ​**推理引擎**​：精通 vLLM、SGLang 或 Ollama 的部署。能够根据业务需求（追求极致延迟 vs 追求高吞吐量）调整推理参数。
* ​**熟悉**​：
  * ​**模型量化与加速**​：了解 AWQ、GPTQ、GGUF 等量化技术，理解 PagedAttention 等显存优化原理，能够在有限硬件下部署更大参数量的模型。

#### 6. 评估、可观测性与安全 (Eval, Observability & Security)

* ​**掌握**​：
  * ​**全链路追踪**​：精通 LangSmith、LangFuse 或 Phoenix。能够对 Agent 的每一次思考、工具调用、耗时进行 Trace 追踪，快速定位 Bad Case。
  * ​**安全与护栏 (Guardrails)**​：掌握防御 Prompt 注入攻击、PII（个人敏感信息）脱敏、输出内容合规性拦截的技术方案。
* ​**熟悉**​：
  * ​**自动化评估体系**​：能够设计 Agent 评估指标（任务成功率、步骤准确率、幻觉率）。掌握使用 LLM-as-a-Judge 或构建自动化测试集（如 AgentBench）进行持续评估。

### 二、 非技术内容深度拆解 (Soft Skills & Cognitive Skills)

很多技术优秀的工程师在做 Agent 时会遭遇瓶颈，往往是因为缺乏以下非技术能力。**这些能力决定了你能否从“写代码的”变成“解决业务问题的专家”。**

#### 1. 业务理解与产品思维 (Business & Product Sense)

* ​**需求拆解与边界定义**​：大模型不是万能的。优秀的开发者能准确判断：​**哪些环节该用大模型，哪些环节该用传统规则，哪些环节该用判别式小模型**​。不“拿着锤子找钉子”。
* ​**ROI（投资回报率）意识**​：在设计方案时算账。用 Agent 自动化处理一个任务，消耗的 Token 成本、算力成本、开发维护成本，是否低于人工成本？如果成本倒挂，技术方案再酷炫也没有业务价值。
* ​**MVP（最小可行性产品）思维**​：面对复杂的 Agent 需求，能迅速剥离边缘场景，用最快的时间跑通核心链路（Core Workflow），然后在真实数据反馈中迭代，而不是闭门造车追求完美。

#### 2. 系统设计与架构思维 (System Design Thinking)

* ​**容错与降级设计**​：大模型具有概率性，一定会犯错、会超时、会宕机。必须设计完善的兜底策略（Fallback）：模型挂了切备用模型？工具调用失败如何重试？陷入死循环如何强制中断？
* ​**状态管理与恢复**​：对于长耗时任务（如运行几个小时的代码生成或数据分析），如何设计 Checkpoint（检查点）机制，确保任务中断后能从断点恢复，而不是从头重来。
* ​**解耦与模块化**​：将 Agent 的“大脑（LLM）”、“记忆（Memory）”、“工具（Tools）”和“工作流（Workflow）”严格解耦，确保系统的高内聚、低耦合，便于独立升级和测试。

#### 3. 提示词工程与“人机交互”设计 (Prompt & HCI Design)

* ​**同理心与意图理解**​：能够站在用户的角度，理解他们“真正想要什么”，而不是仅仅处理他们“字面上说了什么”。
* ​**结构化与逻辑严密的表达**​：System Prompt 就是 Agent 的“源代码”。需要极强的逻辑表达能力，写出无歧义、结构清晰、包含 Few-shot 示例的系统级提示词。
* ​**优雅的引导与交互设计**​：当 Agent 能力不足或信息缺失时，不要直接抛出冷冰冰的错误。要设计优雅的“反问”或“引导”机制，帮助用户补充信息，提升用户体验。

#### 4. 数据治理与质量意识 (Data Governance & Quality)

* ​**对“脏数据”的极度敏感**​：Garbage in, garbage out。Agent 的上限由数据质量决定。能够主动发现业务数据中的噪声、格式不一致、缺失等问题，并推动数据清洗。
* ​**隐私与合规意识**​：在处理企业数据或用户数据时，时刻紧绷合规这根弦。确保数据不泄露、不违规出境，符合 GDPR 或国内的数据安全法规。

#### 5. 跨团队协作与沟通 (Cross-functional Collaboration)

* ​**向上/向外管理预期**​：大模型存在“幻觉”和“能力边界”。必须能够向业务方、产品经理清晰地解释大模型“能做什么”和“不能做什么”，管理好他们的预期，避免项目烂尾。
* ​**与算法团队的“翻译官”**​：能够收集业务端的 Bad Case，将其转化为算法团队能听懂的“数据分布问题”或“模型对齐需求”，推动底层模型的迭代。

#### 6. 持续学习与前沿嗅觉 (Continuous Learning)

* ​**信息源管理与降噪**​：AI 领域每天产生大量信息。需要建立自己的高质量信息源（如 Twitter/X 核心圈、arXiv 特定领域、GitHub Trending、核心开源社区），具备从海量信息中筛选出“真正有业务价值”的技术的能力。
* ​**快速复现与评估能力**​：看到新的论文、新的框架（如刚出的 MCP 或新的 Multi-Agent 架构），能够在 1-2 天内快速跑通 Demo，并客观评估其在当前业务场景下的落地可行性。

### 三、 总结：技术与非技术的协同

在 AI Agent 开发中，**技术能力决定了你能把系统做到多“深”和多“稳”，而非技术能力决定了你能把系统做到多“准”和多“有价值”。**

* ​**初级开发者**​：关注“怎么调用 API”、“怎么写 Prompt”、“怎么把 RAG 跑通”。（侧重技术实现）
* ​**高级开发者**​：关注“怎么优化延迟”、“怎么设计状态机”、“怎么提高检索准确率”。（侧重技术深度与工程化）
* ​**专家/架构师**​：关注“这个业务到底适不适合用 Agent”、“整体 ROI 是多少”、“如何设计容错与降级”、“如何推动跨团队落地”。（侧重业务价值、系统架构与非技术软实力）

如果您正在准备向这个方向发展，建议在夯实 Python、LangGraph、RAG 等技术底座的同时，​**刻意练习自己的业务拆解能力和系统架构思维**​，多去研究优秀的开源 Agent 项目（如 Dify, AutoGen）是如何设计其系统架构和交互流程的。

### ⏱️ 每日标准学习节奏建议 (Daily Routine)

### 🟢 Phase 1: 破冰与底层逻辑 (Day 1 - Day 5)

​**目标**​：脱离“调包侠”思维，理解 LLM 的输入输出本质，手写核心循环。

#### **Day 1: API 深度交互与 Token 经济学**

* ​**技术任务**​：
  1. 配置环境，使用 Python 调用 OpenAI/Claude/智谱 API。
  2. ​**必须实现流式输出 (Streaming)**​：理解 `stream=True` 和 SSE (Server-Sent Events) 协议，这决定了用户体验。
  3. ​**Token 计算**​：引入 `tiktoken` 库，写一个脚本，精确计算输入 Prompt 和输出 Completion 的 Token 数，并乘以单价计算单次成本。
* ​**非技术思考**​：如果我的 Agent 每天处理 10,000 个请求，每次平均消耗 2000 tokens，一个月的 API 成本是多少？我的业务毛利能覆盖吗？

#### **Day 2: 工业级 Prompt Engineering**

* ​**技术任务**​：
  1. 抛弃纯文本 Prompt。学习使用 ​**XML 标签**​（如 `<context>`, `<instruction>`, `<output_format>`）来结构化 Prompt，降低模型幻觉。
  2. 实现 **Few-shot (少样本)** 动态注入：根据用户问题，从向量库检索最相似的 2 个历史 QA 对，拼接到 Prompt 中。
  3. ​**强制 JSON 输出**​：使用 `response_format={"type": "json_object"}`，并编写正则表达式作为兜底，提取模型输出中的合法 JSON。
* ​**避坑指南**​：永远不要相信 LLM 会 100% 遵守格式，必须在代码层做 `try-except` 解析兜底。

#### **Day 3: 徒手实现 ReAct (推理+行动) 循环**

* ​**技术任务**​：
  1. ​**不使用 LangChain**​，纯用 Python `while` 循环实现 ReAct。
  2. 定义 Prompt 模板，要求模型输出 `Thought: ... \n Action: ... \n Action Input: ...`。
  3. 使用正则表达式解析模型的输出。如果解析到 Action，调用对应的 Python 函数；将结果作为 `Observation` 拼接到历史消息中，再次调用 LLM。
* ​**核心收获**​：亲手写过一次 ReAct，你才会明白 LangChain 等框架在底层帮你处理了多少脏活（如解析失败、死循环等）。

#### **Day 4: 拥抱 LangChain LCEL (LangChain Expression Language)**

* ​**技术任务**​：
  1. 学习 LCEL 的核心组件：`RunnablePassthrough`, `RunnableLambda`, `ChatPromptTemplate`。
  2. 使用 `|` (管道符) 将 Day 2 和 Day 3 的逻辑串联起来。
  3. 掌握 `.invoke()` (同步), `.stream()` (流式), `.batch()` (并发) 的区别与使用场景。

#### **Day 5: 阶段项目 1 - 自动化行业研报生成器**

* ​**任务描述**​：输入一个行业（如“2026年低空经济”），Agent 自动拆解为 3 个搜索维度（政策、技术、市场），调用搜索 API（如 Tavily），汇总并生成一份 Markdown 格式的报告。
* ​**交付物**​：可运行的 Python 脚本，包含清晰的日志输出和 Token 成本统计。

### 🟡 Phase 2: 记忆与外挂大脑 (RAG 深度) (Day 6 - Day 12)

​**目标**​：掌握企业级 RAG 的核心链路，解决“检索不准”和“幻觉”两大痛点。

#### **Day 6: 复杂文档解析与高级分块 (Chunking)**

* ​**技术任务**​：
  1. 放弃简单的 `RecursiveCharacterTextSplitter`。
  2. 学习使用 `Unstructured` 或 `LlamaParse` 解析包含表格、图片的 PDF。
  3. ​**核心策略**​：实现“按语义分块”（基于标题层级）或“父子文档检索”（Parent-Child Retriever：小块用于检索，大块用于送给 LLM 提供上下文）。

#### **Day 7: 向量数据库与混合检索 (Hybrid Search)**

* ​**技术任务**​：
  1. 本地部署 `Chroma` 或 `Qdrant`。
  2. ​**必须实现混合检索**​：结合向量检索（Dense，抓语义）和 BM25（Sparse，抓专有名词/精确匹配）。使用 LangChain 的 `EnsembleRetriever` 进行结果融合（RRF 算法）。

#### **Day 8: Rerank (重排序) 与 Query 改写**

* ​**技术任务**​：
  1. 引入 Cross-Encoder 重排序模型（如 `BAAI/bge-reranker-v2-m3`）。在混合检索召回 Top 20 后，用 Rerank 模型重新打分，取 Top 5 给 LLM。
  2. 实现 ​**HyDE (假设性文档嵌入)**​：让 LLM 先根据问题生成一段“假设性答案”，用这段答案去向量库检索，解决“用户提问太短/太口语化导致检索不到”的问题。

#### **Day 9: Function Calling (工具调用) 的 JSON Schema 艺术**

* ​**技术任务**​：
  1. 深入理解 OpenAI/Claude 的 Tool Use 机制。
  2. 手写复杂的 JSON Schema：包含 `enum`（限制选项）、`required`（必填项）、嵌套的 `properties`。
  3. 处理多轮工具调用：当 LLM 需要连续调用 3 个工具才能得出结论时，如何维护上下文。

#### **Day 10-11: 自定义 Tool 与异常处理机制**

* ​**技术任务**​：
  1. 使用 `@tool` 装饰器封装 Python 函数。​**关键：写极其详细的 Docstring**​，因为 LLM 是靠 Docstring 理解工具用途的。
  2. ​**异常处理设计**​：当 Tool 执行报错（如 API 超时、SQL 语法错误）时，​**不要抛出异常中断程序**​，而是将错误信息（Error Message）作为 `Observation` 返回给 LLM，让它自己修正参数并重试。

#### **Day 12: 阶段项目 2 - 智能企业知识库与数据查询 Agent**

* ​**任务描述**​：用户提问。Agent 首先进行​**意图识别 (Router)**​：
  * 如果是“公司报销流程是什么？” -> 走 RAG 检索知识库。
  * 如果是“上个月华东区销售额是多少？” -> 走 Function Calling 调用内部 SQL 查询工具。
* ​**交付物**​：一个带有意图路由的 Agent，能准确区分并处理两类问题。

### 🟠 Phase 3: 骨骼与神经 (LangGraph & 多智能体) (Day 13 - Day 20)

​**目标**​：掌握 2026 年最核心的 Agent 编排框架，实现复杂工作流。

#### **Day 13: LangGraph 核心概念 (状态机)**

* ​**技术任务**​：
  1. 理解 State（状态）、Node（节点）、Edge（边）。
  2. 使用 `TypedDict` 定义 Agent 的状态（如 `messages`, `next_step`, `tool_calls`）。
  3. 构建一个包含条件边（Conditional Edges）的图：根据 LLM 的输出决定是继续调用工具，还是结束对话。

#### **Day 14: LangGraph 进阶 - 持久化与人工介入 (Human-in-the-loop)**

* ​**技术任务**​：
  1. 引入 `Checkpointer`（如 `SqliteSaver`）。实现对话状态的持久化，支持断点续传。
  2. 实现 `interrupt_before`：在 Agent 准备执行“删除数据库记录”等高危 Tool 前，暂停执行，等待人类用户输入 "Approve" 后才继续。

#### **Day 15: 多智能体协同 (Multi-Agent) 架构**

* ​**技术任务**​：
  1. 学习 `CrewAI` 或 `AutoGen`。
  2. 设计角色：定义“需求分析师”、“代码编写者”、“代码审查者”三个 Agent。
  3. 实现 ​**Handoff (交接) 机制**​：理解 Agent 之间如何通过消息传递控制权。

#### **Day 16: MCP (Model Context Protocol) 实战**

* ​**技术任务**​：
  1. 学习 MCP 协议规范。
  2. 使用 Python `mcp` SDK 编写一个 MCP Server。暴露两个工具：`read_file` 和 `query_database`。
  3. 使用 MCP Inspector 或 Claude Desktop 连接你的 Server，验证工具调用。

#### **Day 17-18: 阶段项目 3 - 自动化数据分析与图表生成 Agent**

* ​**任务描述**​：用户上传一个 CSV。
  1. Agent 读取 CSV 前 5 行，分析数据结构。
  2. 根据用户指令（如“分析销量趋势”），Agent 编写 Python (pandas/matplotlib) 代码。
  3. ​**核心难点**​：在沙箱中执行代码。如果报错（如 `KeyError`），Agent 必须读取 `stderr`，进行 ​**Reflexion (反思)**​，修改代码再次执行，最多重试 3 次。
  4. 成功则输出图片。

#### **Day 19-20: 代码重构与架构优化**

* ​**任务**​：将 Day 17-18 的项目，从简单的脚本重构为基于 LangGraph 的标准状态机。将“数据分析”、“代码执行”、“结果总结”拆分为独立的 Node。

  3. 编写脚本，自动计算 RAG 的三大指标：`Faithfulness`（忠实度/有无幻觉）、`Answer Relevancy`（答案相关性）、`Context Precision`（上下文精确度）。

#### **Day 23: 性能优化 - 异步、并发与缓存**

* ​**技术任务**​：

  2. ​**路由**​：实现一个 Router。简单问题（如打招呼、简单分类）路由给 `gpt-4o-mini` / `qwen-turbo`；复杂推理路由给 `gpt-4o` / `qwen-max`。

### 💡 核心避坑指南 (必读)

1. ​**警惕“框架依赖症”**​：LangChain 很好，但不要为了用而用。如果 10 行原生 Python 代码能解决的问题，不要写 50 行 LangChain 代码。**理解底层原理比熟练使用框架更重要。**
2. ​**不要死磕 Prompt**​：当 Prompt 怎么调都达不到 90% 准确率时，停下来。思考是不是该加一个 Tool？是不是该做 RAG？是不是该微调小模型？**系统工程思维 > 提示词技巧。**
3. ​**拥抱“不确定性”**​：传统软件工程是确定性的（1+1=2），Agent 开发是概率性的（1+1 可能等于 1.9 或 2.1）。你的代码设计必须包含**重试、降级、兜底、人工确认**机制，这才是高级工程师的体现。
