### 🗺️ 技术发展路线演进图

#### **阶段一：多模态与垂直领域应用的早期探索 (2024年中 - 2025年初)**

* **代表项目**: `KeyVideoLLM` (2024.06), `Synth-Empathy` (2024.10), `Q-Vid` (2024.11), `Empathy_Eval` (2025.01)
* **路线特征**:
  - 早期关注点在于**多模态理解**（视频 LLM）和**特定情感/交互能力**（Synthetic Empathy）。
  - 开始意识到高质量数据的重要性，尝试使用“合成数据 (Synthetic Data)”来提升特定任务（如共情能力）的表现，并构建相应的评估基准 (`Empathy_Eval`)。
  - **转折点**: 这一阶段为后续全面转向“数据工程”埋下了伏笔。

#### **阶段二：全面拥抱“以数据为中心”的 AI 基础设施 (2025年中 - 2026年初)**

* **代表项目**: `DataFlow` 系列 (`DataFlow`, `DataFlow-WebUI`, `DataFlow-Doc`, `DataFlow-MM-Doc`), `transformers` (Fork), `LlamaFactory` (Fork)
* **路线特征**:
  - **战略转移**: 从“模型微调”转向“数据准备 (Data Preparation)”。深度参与或主导了 **OpenDCAI** (Open Data-Centric AI) 社区的建设。
  - **工程化落地**: 构建了基于最新 LLM 算子的数据管道 (Pipelines)，并配套开发了 WebUI 和多模态 (MM) 文档支持，致力于打造易用的大模型数据清洗与构建基础设施。

#### **阶段三：从“数据准备”升级为“数据优化”与“后训练 (Post-Training)” (2026年春季 - 夏季)**

* **代表项目**: `DataFlex`, `DataFlex-RL`, `DataFlow-PostTrain`, `Synthetic-Math-RLVR`, `DataFlow-Lean`, `DataFlow-MemTensor`
* **路线特征**:
  - **研究深化**: 认识到仅仅“清洗数据”不够，开始研究如何**优化数据**。`DataFlex` 明确指向数据选择 (data-selection)、数据混合 (data-mixture) 和权重调整 (data-reweighting)。
  - **引入强化学习**: 路线延伸至 Post-Training 阶段，探索基于 RL (强化学习) 和 On-Policy Distillation 的训练范式，并率先在难度较高的**数学推理 (Math-RLVR)** 领域进行验证。

#### **阶段四：垂直领域深度赋能与复杂 Agent 评估 (2026年夏末 - 秋季)**

* **代表项目**: `K12-KGraph` (NeurIPS 2026), `Omni-Edu`, `MathDebugger`, `WorkSurface-Bench`, `SciAgent`, `AI-CAD`, `QuantModelBench`
* **路线特征**:
  - **学术爆发与领域落地**: 将前期的数据/训练方法论应用到高价值垂直领域。
    - **🎓 教育领域 (核心重心)**: 发布 NeurIPS 2026 录用的 `K12-KGraph` (课程对齐的知识图谱与多模态数据集)，并推出 `Omni-Edu` (面向教学的基础模型)，形成完整的教育 AI 闭环。
    - **🧠 推理与科学**: 针对数学错误检测 (`MathDebugger`)、科学智能体 (`SciAgent`) 和量化模型 (`QuantModelBench`) 建立专用基准。
    - **🤖 企业级 Agent**: 探索复杂工作流，发布 `WorkSurface-Bench` (多表面知识路由的企业级 Agent 基准) 和 `gh-aw` (GitHub 智能体工作流)。

#### **阶段五：前沿探索：递归自我改进 (RSI) 与学术体系化总结 (2026年秋季 - 至今)**

* **代表项目**: `DataLite-RSI`, `DataVoyager`, `Awesome-LLM-Data-Preparation` (JCST 2026 Survey), `haolpku.github.io`
* **路线特征**:
  - **瞄准 AGI 前沿**: 最新项目 `DataLite-RSI` 探索“递归自我改进 (Recursive Self-Improvement)”，且强调 **Data-Efficient (数据高效)**，这表明团队正在研究如何让模型用更少的数据实现自我迭代进化，这是当前大模型研究的最前沿。
  - **自动化数据智能体**: `DataVoyager` 展示了将 Prompt 直接转化为 QA 训练数据集的 Web Agent 能力，实现了数据生成的自动化闭环。
  - **确立学术影响力**: 发布 JCST 2026 综述的配套 Awesome 列表 (`Awesome-LLM-Data-Preparation`)，对过去几年的“数据为中心”研究进行系统性总结；同时更新个人/实验室主页 (`haolpku.github.io`)，完善学术品牌建设。

### 💡 核心演进逻辑总结

1. **范式转移**: `Model-Centric` (调参/微调) ➔ `Data-Centric` (数据管道) ➔ `Data-Optimization` (数据加权/混合) ➔ `Self-Improvement` (递归自我进化)。
2. **技术栈演进**: 从应用层 (Video/Empathy) ➔ 基础设施层 (DataFlow/WebUI) ➔ 算法层 (RLVR/On-Policy Distillation) ➔ 评估与基准层 (Benchmarks/KGraph)。
3. **应用领域聚焦**: 虽然涉猎广泛 (科学、CAD、量化)，但 **K12 教育 (Education)** 和 **数学/逻辑推理 (Reasoning)** 是该团队产出最密集、学术级别最高 (NeurIPS) 的核心落地场景。

### 🔮 未来路线预测

基于最新的 `DataLite-RSI` 和 `DataVoyager`，该团队下一步的研究重点极有可能是：

1. **完全自动化的数据飞轮 (Data Flywheel)**：利用 Agent (`DataVoyager`) 自动发现模型弱点，自动生成针对性数据，并通过 RSI 机制让模型自我修复和提升，减少对人类标注的依赖。
2. **教育大模型的闭环落地**：结合 `Omni-Edu` 和 `K12-KGraph`，可能会推出端到端的、具备自我进化能力的个性化 AI 导师系统。

## zread.ai（智谱出品）

> **AI 生成结构化 Wiki 文档 + 代码库问答**输入 GitHub 仓库地址，AI 自动分析全仓库，产出​**项目导读、架构拆解、模块说明、架构图**​，可以直接提问代码逻辑；同时提供 MCP 服务，可以接入 Cursor、Claude Code 等 AI 编程助手，适合快速读懂复杂项目、生成项目文档，国内访问更友好腾讯云开发。

## deepwiki.com

> **深度代码知识库 + 深度研究问答**把仓库转为交互式 wiki，自动生成 Mermaid 架构图，支持多级深度代码推理（Deep Research），问答能力强，能追踪跨文件调用链路，同样支持 MCP 接入 AI 编码 Agent，适合研究大型复杂开源项目源码，海外起源，索引仓库数量很多DeepWiki。

## gitingest.com

> **仓库一键打包成 LLM 可用纯文本**​​**不做 AI 总结 / 画图**​。自动拉取代码、过滤掉 node\_modules、二进制等垃圾文件，输出一份「目录树 + 代码全文」的合并文本，附带 token 统计。你复制这段文本直接丢给 ChatGPT/Claude，用来让大模型读整个仓库源码。 核心用途：​**准备代码上下文给大模型**​，轻量、开源，可本地部署PyPI。
