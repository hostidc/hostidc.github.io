# 高考电子答题系统 Java + MySQL + Redis 整体实现思路

## 一、系统整体架构分层（标准 SpringBoot 微服务 / 单体均可，推荐微服务适配高并发考试）

### 技术栈分工

1. ​**Java(SpringBoot/SpringCloud)**​：业务逻辑、接口、权限、答题流程、阅卷、定时任务
2. ​**MySQL**​：持久化核心业务数据（用户、试卷、题目、作答记录、成绩、考场配置）
3. ​**Redis**​：缓存、分布式锁、考试状态管控、防作弊、限时答题、热点数据加速、限流

## 二、MySQL 数据库设计（核心表结构与存储职责）

MySQL 负责​**落地持久化**​，所有不能丢失的数据全部存在 MySQL，Redis 只做临时 / 缓存数据。

### 1. 用户相关表

* `sys_user`：考生、监考、管理员、阅卷老师账号（学号 / 身份证、密码加密、角色、考场分配）
* `student_exam_rel`：考生 - 考场 - 考试批次关联，绑定考生可参加哪些考试

### 2. 考试业务核心表

1. `exam_batch`：考试批次（高考模拟 / 正式统考、考试时间、总分、考试时长、开考 / 截止时间、是否允许交卷）
2. `exam_room`：考场表（考场号、设备限制、最大人数、监考老师 ID）
3. `paper`：试卷主表（科目、总分、创建人、是否启用、难度）
4. `paper_question`：试卷 - 题目关联（题目序号、分值、是否主观题 / 客观题）
5. `question`：题目库（题干、选项、标准答案、解析、题型：单选 / 多选 / 填空 / 作文 / 计算题、素材图片地址）
6. `option`：选择题选项（A/B/C/D 内容）

### 3. 答题 & 成绩表（最核心持久化）

1. `student_answer`：考生作答记录（​**持久化兜底**​，客观题选项、主观题文本 / 图片作答、作答时间、修改次数）
2. `exam_score`：考试成绩（客观自动得分、主观人工得分、总分、交卷状态、阅卷状态）
3. `submit_record`：交卷日志（正常交卷、超时强制交卷、异常掉线重连提交记录）

### 4. 防作弊 / 操作日志表

* `student_operation_log`：考生操作轨迹（切屏次数、页面刷新、登录登出、设备指纹、IP 地址）
* `system_log`：管理员 / 监考操作日志

## 三、Redis 核心使用场景（解决高考系统高并发、限时、防作弊、性能痛点）

Redis 使用 String、Hash、List、Set、分布式锁、过期 Key、Bitmap、限流 Lua 脚本，​**不存永久数据，定时同步到 MySQL**​。

### 场景 1：在线考试状态管控（核心）

1. **考生考试状态缓存 Key 设计**

plaintext

```
# 考生+考试批次 唯一标识
key: exam:status:{studentId}:{batchId}
value: Hash结构
    status: 0未进入/1考试中/2已交卷/3超时强制收卷/4作弊封禁
    enter_time: 进入考场时间戳
    last_active: 最后操作时间戳（检测掉线、切屏）
    screen_switch_count: 切屏次数
    remaining_time: 剩余答题秒数
```

* 过期策略：考试结束时间自动过期，兜底强制交卷
* 作用：不用频繁查 MySQL，实时判断考生是否能答题、能否交卷

2. **分布式锁防止重复交卷、重复提交答案**
   `lock:submit:{studentId}:{batchId}`，提交答案 / 交卷时加锁，避免重复提交产生脏数据。

### 场景 2：实时缓存考生作答（减少 MySQL 高频 IO）

高考同时上千人在线答题，每秒频繁保存选择 / 填空答案，直接写 MySQL 会压垮数据库：

1. Redis Hash 临时存储考生每道题答案

plaintext

```
key: exam:answer:temp:{studentId}:{batchId}
hash: questionId -> 用户作答内容
```

2. 同步策略：
   * 前端每 30s 自动同步一次 Redis 答案到 MySQL（增量更新）
   * 考生手动保存 / 交卷时，全量把 Redis 作答落地到`student_answer`
   * 系统定时任务（5min）兜底同步所有未持久化的作答，防止 Redis 宕机丢数据

### 场景 3：试卷、题目热点缓存（减轻 DB 查询压力）

* 热门试卷完整结构缓存：`paper:info:{paperId}`，考试前预加载到 Redis
* 题目详情缓存：`question:{qId}`，设置过期时间，减少重复查题目库
* 考试开考前预热：批量把本场次所有试卷、题目加载进 Redis，考试期间几乎不访问 MySQL 查题

### 场景 4：限时答题倒计时、超时自动收卷

1. 每个考生 key 设置 TTL 过期时间 = 考试结束时间戳 - 当前时间
2. 搭配 Redis 监听 Key 过期事件（Keyspace Notifications），过期触发回调：
   * 自动标记考生状态为超时收卷
   * 把 Redis 临时作答批量存入 MySQL
   * 自动计算客观题分数写入成绩表

### 场景 5：防作弊能力实现（Redis 高性能统计）

1. **切屏统计**
   前端每次切屏上报，Redis 自增 `screen_switch_count`，超过阈值直接弹窗警告，多次直接强制交卷
   1. **在线心跳检测**
      
      前端 10s 上报心跳更新`last_active`，定时任务扫描 Redis，超过 60s 无心跳判定掉线
      
      1. **同一账号多设备登录拦截**
         
         Set 存储当前在线考生设备标识：`online:student:{studentId}`，新设备登录清空旧设备缓存，强制旧端下线
         
         1. **接口限流防刷**
            
            Redis + Lua 脚本实现滑动窗口限流，限制考生每秒提交答案、查询接口请求次数，防止恶意请求
      
      ### 场景 6：考场在线人数统计、实时大屏
      
      * `exam:online:{batchId}`：当前本场在线考生数量，原子增减
      * Set 集合存储本场在线考生 ID，监考后台实时拉取渲染大屏，无需聚合 MySQL 大数据
      
      ### 场景 7：客观题快速判分缓存
      
      标准答案存入 Redis，考生交卷后直接在内存比对选项，快速算出客观分，大幅提升交卷响应速度，判分结果再持久化 MySQL。
      
      ## 四、Java 业务分层设计（SpringBoot 标准分层）
      
      ### 基础分层
      
      1. ​**Controller 层**​：考生端接口（登录、进入考场、获取题目、保存答案、交卷）；监考端（查看在线、强制收卷、查看切屏记录）；管理员（试卷管理、成绩查询）
      2. **Service 层**
         * ExamService：考试流程、入场校验、倒计时逻辑
         * AnswerService：答案临时缓存、持久化同步、交卷逻辑、客观自动阅卷
         * CheatMonitorService：切屏、心跳、多设备作弊检测
         * RedisCacheService：封装 Redis 工具类（缓存、分布式锁、过期监听、限流）
      3. ​**Mapper/DAO 层**​：Mybatis-Plus 操作 MySQL，只做持久读写
      4. ​**Entity/DTO**​：数据库实体、前端传输对象
      
      ### 核心关键业务流程代码逻辑思路
      
      #### 流程 1：考生进入考试
      
      1. 校验账号密码、校验是否分配本场考试（查 MySQL）
      2. 判断是否已交卷（查 Redis 状态缓存，无缓存再查 MySQL 兜底）
      3. 创建考生考试状态 Hash 存入 Redis，初始化剩余时间、切屏次数
      4. 从 Redis 读取预缓存的试卷题目列表返回前端，不查 MySQL
      5. 加入在线考生 Set，在线人数 + 1
      
      #### 流程 2：前端定时保存答案（高频接口）
      
      1. 获取分布式锁，防止并发提交覆盖答案
      2. 直接写入 Redis 临时作答 Hash，快速返回成功
      3. 异步线程 / 定时任务增量更新 MySQL 作答表，同步数据
      
      #### 流程 3：考生主动交卷（核心事务）
      
      1. 校验 Redis 状态：必须是 “考试中” 才能交卷
      2. 加全局提交锁，防止重复交卷
      3. 读取 Redis 全部临时作答数据
      4. 事务操作 MySQL：
         * 全量覆盖`student_answer`作答记录
         * 读取 Redis 缓存的标准答案，批量计算客观题得分
         * 插入`exam_score`成绩表，标记交卷完成
         * 新增`submit_record`交卷日志
      5. 修改 Redis 考生状态为已交卷，从在线集合移除
      6. 返回客观得分，主观题等待教师后台阅卷
      
      #### 流程 4：Redis 过期自动超时收卷（兜底）
      
      1. 配置 Redis 开启 Key 过期监听
      2. 监听到考生考试状态 key 过期，触发回调方法
      3. 复用交卷同一套逻辑，自动保存作答、计算客观分、标记超时交卷
      4. 记录超时作弊日志
      
      #### 流程 5：防作弊逻辑
      
      * 前端监听窗口切屏、最小化，调用上报接口，Redis 自增切屏次数
      * 定时任务批量扫描 Redis 所有考生`last_active`，无心跳则标记掉线，监考大屏展示异常考生
      
      ## 五、MySQL 与 Redis 数据一致性方案（重点，防止丢答题数据）
      
      高考系统数据不可丢失，必须保证双端一致：
      
      1. **缓存更新策略：先 Redis，异步更新 MySQL**
         答题保存先写 Redis，使用 Spring 异步线程池异步落库，前端无等待延迟
         1. **定时兜底同步任务**
            
            每 5 分钟执行定时任务：遍历所有 Redis 临时作答，对比 MySQL 作答记录，同步未持久化的数据
            
            1. **交卷全量落地**
               
               只要考生交卷 / 超时收卷，强制全量把 Redis 作答写入 MySQL，以 MySQL 数据为准
               
               1. **Redis 宕机恢复方案**
                  
                  * Redis 开启 RDB+AOF 持久化，重启自动恢复缓存作答
                  * 定时任务兜底，即使 Redis 全部丢失，最近一次 MySQL 增量同步的数据不会完全丢失
               2. **最终一致性，不要求强一致**
                  
                  答题过程允许短暂缓存与 DB 不一致，交卷时强制统一，符合考试业务场景
            
            ## 六、高并发与性能优化方案
            
            ### MySQL 优化
            
            1. 索引优化：考生 ID、考试批次 ID、题目 ID、联合索引（student\_id + batch\_id）
            2. 读写分离：主库写入作答、成绩，从库提供试卷查询、成绩统计大屏
            3. 分表：作答记录量大时按考试批次分表`student_answer_2026_gk1`
            4. 事务控制：交卷操作使用 MySQL 事务，保证作答、成绩、日志同时写入或回滚
            5. 避免长事务，高频保存答案只用异步单条 update，不开启事务
            
            ### Redis 优化
            
            1. 集群部署：Redis Cluster 分片，分散大量考生缓存 key，避免单机内存溢出
            2. 冷热分离：试卷、标准答案长期缓存；考生答题状态、临时作答设置过期时间
            3. 使用 Hash 压缩存储，减少 key 数量，节省内存
            4. 分布式锁使用 Redisson，避免原生 SETNX 死锁问题
            5. Lua 脚本批量操作：批量保存答案、批量统计在线人数，减少网络 IO
            
            ### Java 服务优化
            
            1. 线程池分离：同步答题线程、异步落库线程、定时任务线程隔离
            2. 接口异步化：心跳上报、切屏记录采用异步处理，不阻塞主线程
            3. 预热加载：开考前半小时定时任务把本场所有试卷题目批量加载到 Redis，考试零 DB 查询
            
            ## 七、拓展功能实现思路
            
            1. **主观题阅卷**
               MySQL 存储考生作文 / 计算题作答文本、图片；Redis 缓存待阅卷列表，阅卷老师批改后更新 score 表。
               1. **成绩统计分析**
                  
                  定时任务从 MySQL 聚合各科平均分、错题率，结果存入 Redis，大屏快速展示。
                  
                  1. **断线重连**
                     
                     考生重新登录后从 Redis 读取临时作答，恢复上次答题进度，无缓存则读取 MySQL 历史作答。
                     
                     1. **批量导出答题卡 / 成绩**
                        
                        异步任务查询 MySQL 生成 Excel，文件地址缓存 Redis，前端轮询下载。
                  
                  ## 八、整体流程总结
                  
                  1. 考前：MySQL 存储试卷题目，Java 定时任务批量预热到 Redis；分配考生考场存入 MySQL 关联表。
                  2. 考中：考生答题数据先写 Redis 高速缓存，异步同步 MySQL；Redis 管控倒计时、在线状态、切屏作弊统计；心跳实时监控考生在线状态。
                  3. 交卷 / 超时：Java 读取 Redis 作答，MySQL 事务持久化全部答案，自动批改客观题；更新考试状态，清理 Redis 在线缓存。
                  4. 考后：MySQL 永久保存作答与成绩，Redis 缓存统计数据用于大屏展示，阅卷系统读取 MySQL 主观题批改打分。
