# 虚拟 AI（数字 AI）vs 物理 AI（实体 AI）

一句话总结：​**虚拟 AI 在屏幕里处理信息、只会动脑；物理 AI 在现实世界感知动手、能改造实物**​。

## 一、什么是虚拟 AI（Digital AI）

虚拟AI概念示意

​**定义：只运行在软件、服务器、数字世界里，无实体躯体，只处理文字、图片、数据的人工智能**​。

### 核心特点

1. **生存空间：纯数字环境（手机 / 电脑 / 云端），碰不到现实实物**
2. ​**训练数据：网页文本、图片、音频、代码，靠人类互联网数据学习​**​，**不懂重力、摩擦力、空间、软硬等物理规则**
3. **能力：生成文案、画画、聊天、数据分析、写代码、答疑；能告诉你怎么拿杯子，但亲手拿不了杯子**

### 常见例子

ChatGPT、文心一言、AI 绘画（Midjourney）、语音助手 Siri、AI 数字人、短视频文案 AI、推荐算法。

> 举例：你问 “怎么倒水不洒”，虚拟 AI 能写详细步骤，但没法真拿起水杯倒水。

## 二、什么是物理 AI（Physical AI，具身 AI）

​**定义：搭载传感器 + 机械硬件，能感知真实环境、理解物理规律、在现实世界自主行动的人工智能，打通数字大脑和实体躯体**​。

### 核心特点

1. **生存空间：现实物理世界，自带硬件（摄像头、雷达、电机、机械臂、底盘等）**
2. **训练数据：3D 空间、环境影像、传感器实时数据、物理仿真数据，学会重力、碰撞、材质软硬、受力大小**
3. **能力：感知→思考→动手→纠错闭环，能实实在在操控实体物品、适应环境变化**

### 常见例子

自动驾驶汽车、家用扫地机器人、工业机械臂、人形机器人（优必选、特斯拉 Optimus）、仓储搬运机器人、无人机自主避障飞行。

> 举例：物理 AI 机器人看懂水杯，自动控制握力、倾斜角度，平稳倒水不洒，手滑会立刻调整姿势。

现在行业趋势：​**虚拟 AI 是 AI 上半场（内容生成），物理 AI 是 AI 下半场（落地实体）**​，很多物理 AI 的大脑底层，依然借用虚拟大模型的语言理解能力，再加物理感知模块变成实体智能。

# 一句话精准概括算力链路：​**GPU 算、存储存、光模块运**​，三者构成 AI 算力三角

## 1. GPU：算力大脑（负责「计算」）

* 任务：跑大模型参数、矩阵运算、AI 推理 / 训练，海量浮点计算
* 短板：​**容量极小、断电数据清空**​，算完的数据不能长期留在 GPU 里

## 2. 存储（内存 + 硬盘 / SSD）：数据仓库（负责「存放」）

* ​**内存（显存 / 主机内存）：临时存**​，GPU 要用的数据提前拉进来，高速临时缓存
* ​**SSD / 磁盘：永久存**​，海量训练数据集、模型权重、原始数据长期落地保存
* 短板：​**没法远距离高速搬家数据**​，存储和 GPU、机房之间远距离传输靠光模块

## 3. 光模块：高速物流（负责「运输」）

### 运输三层场景

1. ​**GPU ↔ 本地存储**​：单机内部数据搬运
2. ​**单机 GPU ↔ 集群其他服务器 GPU**​：多卡多机分布式训练（大模型训练核心）
3. ​**机房 ↔ 外部数据中心 / 云端**​：跨地域数据互通

* 原理：电信号转光信号，光纤传输，速率远高于铜线，**AI 超算集群全靠光互联**
* 短板：只做传输，不算数据、不存数据

## 完整 AI 数据流闭环

`存储读出数据 → 光模块高速运输 → GPU接收运算 → 运算结果再经光模块运回存储保存`

## 补充延伸

1. ​**算力涨价逻辑**​：AI 大模型需要海量 GPU 并行，集群互联需求暴涨→光模块需求爆发；数据集越来越大→存储扩容；模型参数暴涨→GPU 需求激增。
2. 配套：交换机配合光模块做数据路由，相当于「物流中转站」。

## 一、第一层：单机服务器内部组网（一台 8 卡 H100 主机）

### 1. GPU 之间：NVLink 直连（机箱内部高速小路，不用光模块）

* 8 张 GPU 靠**NVLink 高速铜缆**全互联，​**卡和卡显存直接互通**​，张量并行、小参数同步在本机内部搞定，不走交换机、不走光纤。
* 作用：​**本机内部算力抱团**​，单台机器 8 卡当成一块超大虚拟 GPU。

### 2. GPU ↔ 本机 SSD：GPUDirect 直连

本地 NVMe 固态硬盘绕过 CPU，数据​**直接进 GPU 显存**​，本机小数据集就近读取。

### 3. GPU 外接高速网卡（RDMA 网卡）：出机箱的 “高速收费站”

每张 GPU 对应独立 400G/800G RDMA 网卡（RoCE/IB 网卡），网卡插​**光模块**​，引出光纤连机柜交换机，​**本机 GPU 的数据要出机架全靠它外运**​。

> 小结：​**机箱内 NVLink 短途跑，出机箱光模块长途运**​。

## 二、第二层：整机架 / 全集群组网（Spine-Leaf 叶脊两层架构，AI 集群标配）

AI 大模型 90% 流量是​**东西向（服务器↔服务器 GPU 互传参数）**​，南北向（连外网 / 冷存储）占比极低，所以用扁平两层 Clos 架构，无汇聚层。

### 1. Leaf 交换机（叶交换机：接入层，机架内）

* 每个机柜配 1\~ 多台 Leaf 交换机，​**所有服务器网卡光纤→Leaf 交换机（全用光模块对接）**​。
* 角色：​**小区门口快递站**​，收集本机架所有 GPU 发出来的数据，统一向上转运。

### 2. Spine 交换机（脊交换机：核心层，独立机房机柜）

* 所有 Leaf 交换机​**全连接所有 Spine 交换机（全光纤 + 400G/800G 光模块）**​，全互联无阻塞。
* 角色：​**国家级高速枢纽**​，不同机架、不同机房的 GPU 数据在这里中转。

### 完整跨机数据路径

`GPU显存→RDMA网卡→光模块→光纤→Leaf交换机→光模块→光纤→Spine交换机→光纤→Leaf→目标服务器网卡→对端GPU`

> 光模块 = 整条链路每一段的运输接口，Leaf、Spine、服务器网卡三方端口全都要插光模块，​**万卡集群光模块数量≈GPU 数量 ×4\~6 倍**​。

## 三、集群三张物理隔离网络（三套独立光纤 + 交换机，互不串流）

### 1、计算网（核心网，参数面，最贵带宽最高）

* 用途：​**GPU 之间传模型参数、梯度更新（大模型训练主力流量）**​，最吃带宽、要零丢包低延迟。
* 方案：IB（InfiniBand）NDR400G/800G 或 以太网 RoCEv2 无损网络，全链路 400G + 光模块。
* 场景：千亿大模型分布式训练，多机 GPU 每时每刻互相同步权重。

### 2、存储网（数据面，GPU↔共享存储）

* 用途：GPU 读取训练数据集、保存模型断点 Checkpoint，对接全集群分布式共享存储池（全闪 SSD 集群）。
* 链路：共享存储服务器→光模块→Leaf/Spine→计算 GPU；支持 GPUDirect，存储数据直达显存，不走 CPU 内存。
* 三级存储落地：冷存（对象存储）→高速共享全闪存储→GPU 显存。

### 3、管理运维网（低速 10G 以太网）

* 用途：服务器开关机、硬件监控、集群任务调度、日志上传，流量极小、带宽要求低，普通网线即可，极少用光模块。

## 四、数据流完整闭环（GPU 算、存储存、光模块运落地演示）

1. ​**存储**​：共享 SSD 数据集静态存放；
2. ​**运（光模块）**​：存储网光纤 + 光模块把批量训练数据从存储集群运送到各服务器 GPU；
3. ​**算（GPU）**​：GPU 完成一轮训练计算，生成梯度参数；
4. ​**再运（光模块）**​：计算网光纤 + 光模块在全集群同步所有 GPU 参数；
5. ​**回存（存储）**​：训练断点经存储网运回共享 SSD 永久保存。

## 五、行业两种组网路线区别

1. ​**IB 组网（超大规模万卡集群：英伟达超算、头部智算中心）**​：专用无损网络、延迟更低、成本高、IB 专用光模块；
2. ​**RoCE 以太网（中小型算力、云厂商）**​：通用以太网改造 + RDMA、兼容普通光模块、性价比高，500 卡以内首选。
