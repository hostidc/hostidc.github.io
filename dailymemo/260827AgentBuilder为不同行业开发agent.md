跨行业 Agent Builder"的转型。让我把它从抽象判断落到可执行方案。

## 一、先定位你的真实角色

"为不同行业开发 agent" 这个说法里有 3 种完全不同的生意，先认清你做的是哪一种，后面的打法完全不同：

| 模式                   | 你是谁              | 卖的是什么            | 典型客户             |
| ------------------------ | --------------------- | ----------------------- | ---------------------- |
| A. 通用 Agent 平台     | "中国的 Agentforce" | Agent 框架 + 编排引擎 | 中大型企业的 IT 部门 |
| B. 垂直 Agent 产品 ⭐  | "医疗版的 Devin"    | 解决某个具体业务问题  | 行业里的一线业务团队 |
| C. Agent 实施咨询 ⭐⭐ | "Agent 集成商"      | 帮客户改造工作流      | 传统行业的中大型客户 |

我的强烈建议：B + C 组合——做垂直产品建护城河，靠咨询养团队、做案例、拿数据。 纯 A 太卷（头部已经被 Salesforce/Autogen/CrewAI 占了），纯 C 天花板低。

下面默认你走 B + C。

## 二、选行业的 5 个判断标准（别凭感觉）

不是每个行业都值得做。用这 5 条筛一下：

1. 数据电子化程度 ≥ 60%（OCR/表单/邮件至少有一种数字化输入）
2. 流程有明确的"判断节点"（不是纯体力活）
3. 决策可逆性高（错了能撤回，agent 才好上手）
4. 行业毛利 ≥ 30%（客户付得起 agent 的钱）
5. 现有 SaaS 渗透率 < 50%（还有改造空间）

按这个筛，最容易起步的 3 个行业：

* 🥇 财税代理 / 中小会计师事务所——流程极度重复、判断节点清晰、错了能补
* 🥈 跨境电商运营——多语言 + 多平台 + 数据驱动，agent 是天然解
* 🥉 律所的合同审查 / 知识产权——文档密集、判断规则化

最难起步但天花板最高：

* 医疗（监管重）、教育（付费方不清晰）、政务（决策慢）

## 三、做一个垂直 Agent 产品的标准路径

### 阶段 0：选场景（2–4 周）

不要做"行业大模型"，要做"行业里某个人一周干的事"。

举个反例和正例：

* ❌ "我做一个法律 AI"——太宽
* ✅ "我做一个律所的 合同初审 Agent"——这个律师每周要审 50 份合同，80% 时间花在找条款异常

找场景的 3 个方法：

1. 去 5 个目标客户那里跟着干一天（不要采访，要观察）
2. 问"你一周做的哪件事最讨厌？"——答案就是场景
3. 找那种"必须资深员工才能做、新人做要培训 3 个月"的活——agent 最容易出价值

### 阶段 1：手工复制流程（2–3 周）

这一步最反直觉也最关键：

* 你自己手动把目标客户的 5–10 个真实任务做完
* 写下每一步的判断依据
* 标出"哪些步骤必须人来"——这是你 agent 的边界

产出物：一份 10–20 页的《[行业] [场景] 操作手册》——这是你后面所有微调数据的母版。

### 阶段 2：搭第一版 Agent（4–6 周）

用 Qwen3.8-27B + Qwen3Guard-Stream 作为底座：

关键工程决策：

* 80% 用规则 + 传统 ML，20% 用 LLM——别一上来就全 LLM
* 审批模型 = Qwen3Guard-Gen-4B（直接用现成的，不要重新训）
* 每一个 agent 输出都必须可解释——客户要看到"为什么这么判"
* 置信度门是必选项，不是可选项

### 阶段 3：找 3–5 家"灯塔客户"（4–8 周）

不要直接卖，先免费做 3 个：

* 选 3 个愿意开放数据 + 愿意吐槽的客户
* 每周迭代一次
* 让他们骂你——他们骂什么你就要改什么

这一阶段的隐藏产出：

* 500–2000 条真实标注数据（金标准）
* 3 个可对外讲的案例故事
* 5–10 个行业里愿意转介绍的人

### 阶段 4：把流程做成可复用产品（3–6 个月）

把你前 3 阶段做的"为 A 公司定制的 agent"，抽象出 70% 的通用部分 + 30% 的客户配置：

* 通用部分 = agent 工作流、UI、模型推理
* 客户配置 = 行业规则、知识库、品牌语气

这就是你 SaaS 化的 PMF。

## 五、定价模型（最容易踩的坑）

3 种主流定价，强烈推荐第三种：

| 模式      | 例子            | 问题                                 |
| ----------- | ----------------- | -------------------------------------- |
| 按席位    | \$200/人/月     | 客户砍人头，agent 越能干客户越少     |
| 按调用    | \$0.05/次       | 客户焦虑账单，不敢用                 |
| 按结果 ⭐ | \$50/份合同审完 | 客户和你的利益对齐：agent 越准你越赚 |

合同审查 agent 的定价示例：

* 基础版：\$30/份
* 含人工复核：\$80/份
* 企业版包月：$5000/月 +$5/份

这一招的关键：把"agent 失败"变成你的成本而不是客户的风险——这样客户才放心用。

## 六、最容易死掉的 3 个坑（避开能省 12 个月）

### 坑 1：上来就做"通用 Agent 平台"

死因：和 LangChain、Salesforce、Autogen 正面竞争。解药：永远只解决一个行业的一个场景。

### 坑 2：上来就追求"完全无人"

死因：客户不敢把关键流程交给黑盒。解药：人机协作是产品，不是过渡方案。Agent + Human-in-the-loop 才是常态。

### 坑 3：用通用 LLM 硬扛行业术语

死因：客户一上来问"这个条款在我们的地区合规吗"，通用模型胡说八道。解药：

* 领域微调（Qwen3.8-27B + LoRA，2000 条样本）
* 知识库外挂（不要把所有知识塞进 prompt）
* 专家审核面板（让领域专家持续贡献判断 → 反哺数据）

## 七、启动的前 90 天行动清单

如果你下周一就开始，按这个节奏：

第 1–2 周：选 1 个行业（建议财税代理或律所合同审查），约 5 个潜在客户深聊，每人 1 小时。

第 3–4 周：去 1–2 个客户那里跟着干 3 天，写出 10 页的操作手册。

第 5–6 周：用 Qwen3Guard-Gen-4B + Qwen3.8-27B 搭一个最粗糙的 PoC——能跑就行，别追求好看。

第 7–8 周：找 1 个客户免费试用，每天一起复盘，记下所有问题。

第 9–10 周：根据反馈改第 2 版，加上 Qwen3Guard-Stream 实时审核。

第 11–12 周：签下第一个付费客户（哪怕 \$500/月），开始有收入循环。

## 八、一个反直觉但决定生死的建议

> 你做垂直 agent 最大的护城河不是模型，是数据。

不是技术数据，是业务判断数据——"这种合同应该这么处理"、"这个客户应该这么回复"。

这个数据从哪里来？ 从你免费给前 3 个客户做实施的过程中来。为什么别人复制不了？ 因为他们不去做咨询、不去陪客户骂你。为什么这么重要？ 因为训练一个垂直 agent 的真正瓶颈不是模型架构，是你有没有 5000 条带专家标注的真实判断。

所以我建议你把"前 3 个客户"当成"前 3 个数据采集项目"来打——付钱给客户也值得。
