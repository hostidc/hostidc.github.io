### 一、 核心模块详细设计：消息路由网关（后端）

这是整个系统的“大脑”，负责在用户、FastGPT 和人工客服之间搬运消息。

#### 1. 数据库设计 (MySQL/PostgreSQL)

需要设计 4 张核心表：

* ​**`sessions` (会话表)**​：记录用户与系统的会话状态。
  * 字段：`session_id` (主键), `channel` (渠道: web/wx\_mp/wx\_work), `openid` (用户唯一标识), `status` (状态: AI/HUMAN/WAITING), `agent_id` (当前分配的人工客服ID), `created_at`, `updated_at`。
* ​**`messages` (消息记录表)**​：统一存储所有聊天记录。
  * 字段：`msg_id`, `session_id`, `role` (user/ai/agent/system), `content` (文本或JSON), `created_at`。
* ​**`agents` (客服坐席表)**​：管理人工客服。
  * 字段：`agent_id`, `username`, `password_hash`, `nickname`, `status` (online/offline/busy)。
* ​**`quick_replies` (快捷回复表)**​：客服常用的话术库。
  * 字段：`reply_id`, `agent_id`, `title`, `content`。

#### 2. 会话状态机设计 (核心逻辑)

状态流转必须严谨，防止消息丢失或错乱：

* ​**初始状态 (`AI`)**​：用户发消息 -> 网关拦截 -> 调用 FastGPT API -> 返回 AI 回复。
* ​**触发转人工**​：
  * 用户输入关键词（如“转人工”）。
  * FastGPT 工作流返回特定标记（如 `[TRANSFER_HUMAN]`）。
  * 状态变为 `WAITING` -> 寻找空闲客服 -> 状态变为 `HUMAN`。
* ​**人工接待 (`HUMAN`)**​：用户发消息 -> 网关拦截 -> 通过 WebSocket 推送到客服工作台 -> 客服回复 -> 网关通过渠道 API 发送给用户。
* ​**结束人工 (`AI`)**​：客服点击“结束服务/交还AI” -> 状态变回 `AI` -> 发送一条系统提示“已为您转回智能客服”。

#### 3. FastGPT API 对接封装

* ​**接口**​：使用 FastGPT 的 `/api/v1/chat/completions`。
* ​**上下文处理**​：每次调用时，将 `session_id` 传给 FastGPT，FastGPT 会自动在它的数据库里维护上下文，网关不需要自己拼接历史消息（极大简化开发）。
* ​**流式 vs 非流式**​：建议初期使用​**非流式 (stream: false)**​，逻辑更简单；后期为了体验好，可改为 SSE 流式输出。

### 四、 关键难点与“避坑”解决方案

#### 1. 微信 5 秒超时问题（必坑）

* ​**现象**​：微信公众号要求服务器在 5 秒内返回 XML，否则微信会提示“该公众号暂时无法提供服务”，并重试 3 次。但 AI 生成回复通常需要 5-15 秒。
* ​**解决方案**​：
  1. 收到微信消息后，网关**立即**返回空字符串 `<xml></xml>`。
  2. 网关在后台异步调用 FastGPT。
  3. FastGPT 返回结果后，网关调用微信的 **“发送客服消息”接口** (`/cgi-bin/message/custom/send`)，将 AI 回复主动推送给用户。

#### 2. 消息乱序与丢失问题

* ​**现象**​：WebSocket 在网络波动时，可能导致客服收到的消息顺序错乱，或者漏收。
* ​**解决方案**​：
  * 所有消息在存入数据库时，生成一个全局递增的 `sequence_id` (或使用数据库自增 ID)。
  * 前端渲染时，严格按照 `sequence_id` 排序。
  * 引入 ​**ACK 机制**​：网关发送消息给客服工作台后，工作台返回一个 `ACK: msg_id`，如果网关 3 秒没收到 ACK，则重发。

#### 3. FastGPT 宕机降级策略

* ​**现象**​：大模型 API 偶尔会抽风，或者 FastGPT 服务器内存溢出宕机。
* ​**解决方案**​：在网关层做​**熔断降级**​。如果调用 FastGPT 连续失败 3 次，自动将新会话的状态直接设为 `WAITING`（转人工），并给用户回复：“智能客服正在维护，已为您优先转接人工客服”。

### 三、 核心改造代码示例 (Go 语言)

以下是在 GoFly 的消息处理链路中，加入 **“国标合规拦截与转人工”** 的核心逻辑示例：

```go
package main

import (
	"encoding/json"
	"strings"
	// 假设您使用了 http 客户端调用 FastGPT
)

// 敏感词库 (根据国标要求，涉及资金、维权等需人工兜底)
var sensitiveKeywords = []string{"退款", "赔偿", "投诉", "合同", "价格修改", "人工", "真人"}

// HandleUserMessage 处理用户发来的消息
func HandleUserMessage(sessionID string, userID string, userMessage string) {
	// 1. 国标合规检查：是否包含敏感词或主动要求转人工
	if containsSensitiveWord(userMessage) {
		// 直接转人工，不调用 AI
		TransferToHumanWithPriority(sessionID, userID, "触发敏感业务/用户要求，按国标要求优先转接人工")
		SendMessageToUser(sessionID, "涉及资金/合同安全或您要求人工服务，正在为您优先转接高级人工客服，请稍候...")
		return
	}

	// 2. 调用 FastGPT API
	fastgptResponse, err := CallFastGPTAPI(sessionID, userMessage)
	if err != nil {
		// AI 服务异常，按国标要求，必须兜底转人工
		TransferToHumanWithPriority(sessionID, userID, "AI服务异常，兜底转人工")
		SendMessageToUser(sessionID, "智能系统暂时繁忙，已为您转接人工客服。")
		return
	}

	// 3. 检查 FastGPT 是否返回了“需要人工”的标记 (需在工作流中配置)
	if strings.Contains(fastgptResponse.Text, "[NEED_HUMAN]") {
		TransferToHuman(sessionID, userID, fastgptResponse.History) // 传递完整历史上下文
		SendMessageToUser(sessionID, "您的问题需要人工协助，正在为您转接...")
		return
	}

	// 4. 正常返回 AI 回复
	SendMessageToUser(sessionID, fastgptResponse.Text)
}

// TransferToHumanWithPriority 将会话转交人工，并附带完整上下文 (国标核心要求)
func TransferToHumanWithPriority(sessionID string, userID string, reason string) {
	// 1. 获取该 session 的所有历史对话 (用户与AI的交互)
	history := GetChatHistory(sessionID)
	
	// 2. 调用 GoFly API，创建或更新会话状态为人工，并标记为高优先级
	payload := map[string]interface{}{
		"session_id": sessionID,
		"user_id":    userID,
		"status":     "HUMAN",
		"priority":   "HIGH", // 高优先级
		"reason":     reason,
		"history":    history, // 【关键】将上下文推给 GoFly 工作台
	}
	
	// 3. 发送 API 请求给 GoFly 后端
	_, _ = http.Post("http://gofly-backend/api/v1/session/transfer", "application/json", toJSON(payload))
	
	// 4. 触发 GoFly 工作台的新会话弹窗/声音提醒
	NotifyAgentWorkspace(sessionID)
}

func containsSensitiveWord(msg string) bool {
	for _, keyword := range sensitiveKeywords {
		if strings.Contains(msg, keyword) {
			return true
		}
	}
	return false
}
```
